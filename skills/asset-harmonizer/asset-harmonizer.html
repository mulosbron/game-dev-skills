1 · Inventory and Triage

The first stage of the pipeline is knowing what you have (Section 4): each file's polygon count, bounding box dimensions, material count, UV and texture status are reported; a keep / repair / redo / discard decision is made for every asset. The unit convention is guessed automatically (m / cm / mm) and can be changed manually in the inventory table.

2 · Geometric Normalization

Every file is fitted to the same rules (Section 5). Order is critical: apply transform → pivot → cleanup → normals → decimate. Apply transform is done automatically on import (node matrices are baked into positions); negative scale is reported if detected.

3 · UV and Texel Density

All assets are fitted to a common px/cm standard (Section 6). Measurement: TD = √(uvArea × W × H ÷ worldArea_cm²). The tool multiplies all UV islands by a single scale; use Blender + Texel Density Checker for per-island fine tuning. Assets without UVs get an automatic box unwrap.

If no texture is assigned, the class default texture size is used.

4 · Texture Re-Styling (AI-free)

Pulls textures into the game's visual language without any AI (Section 7): palette quantization, PBR map derivation (Materialize-like) and AI-free upscaling (Lanczos + unsharp; deliberately chosen in place of Real-ESRGAN). Order rule: ① Upscale → ② Derive PBR → ③ Palette remap. The palette pass is applied only to albedo maps; normal/roughness data maps are never touched.

5 · Engine Integration Preview

An in-browser simulation of the engine-side integration layer (Section 9): a single master shader (lambert), palette remap, .cube LUT, ACES tonemap, one directional sun + ambient, fog. It fits the whole scene into a single color world without touching any texture — so it is tried before costly retexture work. "Clay" mode is the 5-minute diagnostic test from Section 2.

6 · Quality Gate

Definition of Done (Section 4.3) — the automatic half of the checklist is audited here: naming pattern, size, pivot, polygon ceiling, UV presence, texel density deviation (≤5%) and texture saturation ceiling. Visual consistency and the scene test are human work. An asset that fails is reported together with the stage it should return to.

7 · Automation — Run the Pipeline

The browser version of Guide 10.1: the selected stages run in order over the entire stock. If a step fails on a file, the pipeline does not stop; it goes into the report and is added to the triage list. Assets with the decision "discard" / "redo" are left for manual work.

8 · Reference — Folder Architecture, Plan and Limits

Folder architecture (Guide 3.6)

project/
   docs/            style_guide.md, qa_report.md
   assets_source/   raw files — the engine never looks here
   assets_runtime/  the only folder the engine sees
   pipeline/        this tool's outputs: inventory.csv, *_norm.obj, *_pal.png

Two-tree rule: source never enters the engine; the runtime folder can always be regenerated from the pipeline.

Deliberate limits

  • FBX is not read — binary format; export as OBJ/GLB from Blender (Section 5.5).
  • Section 8 (local AI texturing) is out of scope — living up to the tool's name: it is completely AI-free.
  • Lanczos + unsharp is used instead of Real-ESRGAN (AI-free upscaling).
  • Bake (6.4), atlas packing (6.3) and retopo → stay on the Blender / Instant Meshes / xatlas side.
  • Decimate is vertex-clustering based: sufficient for background/midground, not for hero assets.
  • All processing runs locally in the browser; no file is uploaded and no network request is made.
