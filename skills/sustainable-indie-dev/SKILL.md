# Sustainable Indie Dev

Most indie projects fail before the first line of code — from bad scoping, not bad coding. This skill covers the non-mechanical half of game development: planning, producing, shipping, marketing, and surviving the process mentally.

## The Formula

Produce cheap and fast → Build modular systems → Design strong hooks → Build your audience → Get continuous feedback

## Before You Code

1. **Scope down.** Never start with the dream game. Pick small, finishable projects. Ask: "How many years can I sustain this?" Then halve it — that's your real timeline.
2. **Build systems, not games.** Inventory, AI, dialogue, movement — these survive idea changes. Games don't.
3. **Play to your strengths.** Can't model in 3D? Pick pixel-art or isometric. Don't fight your weaknesses; route around them.
4. **Modularize.** Reuse pieces across projects. Pre-made parts beat spaghetti code every time.
5. **Pivot when needed.** If a mechanic feels dead in practice, reshape it. Ideas on paper rarely survive contact with playtesting.

## Technical Production

- **Pick one engine, master it.** 2D → GameMaker/Godot. 3D → Unity/Unreal. The engine matters less than the discipline.
- **Escape tutorial hell.** Question every line you copy. Understanding > copying.
- **Lower production costs.** Asset stores, stock music, AI tools — use them. Compete on creativity, not graphics.
- **Test builds early.** Editor ≠ shipped game. Learn the export pipeline on day one.

## The Trinity Hook

Every marketable game needs three hooks:
1. **Story hook** — a narrative that grabs attention
2. **Mechanic hook** — gameplay that's unique
3. **Visual hook** — art style that stops the scroll

Missing any one kills discoverability.

## Marketing Is Not Optional

- **Set up Steam page early.** Wishlists take months to build.
- **Build your own audience.** 10,000 loyal followers > any publisher deal or algorithm.
- **Ship a polished 15-min demo.** It's your business card — for players and investors.
- **Share the journey.** Devlogs, progress posts, behind-the-scenes. People follow the developer, not just the game.
- **Never market on hope alone.** "If it's good, it'll sell" is not a plan.

## Developer Psychology

- **Motivation fluctuates, discipline doesn't.** On bad days, one line of code or one sprite still counts.
- **Burnout is real.** Stepping away is productive, not lazy.
- **Small wins compound.** "I finished the inventory system today" beats "I'm 2% through my dream game."
- **Don't work alone if you can help it.** An artist, a musician, or even an accountability partner changes everything.
- **Community is fuel.** Share early. Even a single "looks cool" comment can carry you through a tough week.

## Diagnostic: Why Is My Project Stuck?

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| Lost motivation after 2 weeks | Scope too large | Cut scope in half, ship a prototype |
| Code is a mess | No modularity | Extract systems into reusable modules |
| No one cares about the game | Missing hooks | Apply Trinity Hook — which of the three is weak? |
| Demo gets no traction | No audience built | Start devlogs, set up Steam page, engage community |
| Keep restarting the same project | Fear of commitment to one design | Pick the smallest finishable version and ship it |
